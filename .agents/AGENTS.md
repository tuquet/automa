# Git Repository Rules

- **NEVER** use `git commit` or `git push` on your own accord.
- Pushing code to remote is an important, sensitive action. **ONLY the USER** is allowed to push code and use `git push`.
- Unless explicitly asked by the USER, leave all completed changes in the Staging Area or Working Directory for the USER to review and commit manually.

# UI Development Rules

- **STRICTLY USE SHADCN-VUE COMPONENT LIBRARY.**
- Do NOT mock UI components using raw Tailwind CSS classes on standard HTML elements unless absolutely necessary.
- Always install components properly via 
px shadcn-vue@latest add <component> first.
- Utilize the installed components (e.g. @/components/ui/...) instead of recreating them.
- Ensure components.json and 	sconfig.json paths are properly configured for the CLI before installing.
- **NEVER** manually modify the core UI component files downloaded by the Shadcn CLI (e.g., files inside `src/components/ui/`). These files must remain exactly as generated by the CLI. If a core component has bugs or styling issues (like version mismatches), solve them externally at the component's usage site or by adjusting global configurations (like Tailwind config), rather than editing the core file itself.
- **Colorless Theme Requirement**: This project uses a strictly neutral, monochrome (colorless) theme. NEVER hardcode raw Tailwind color classes (like `text-red-500` or `bg-blue-600`). You must strictly rely on Shadcn's neutral semantic CSS variables.
- **Strictly Monochrome Components**: Do NOT attempt to attach colored variants to Buttons or Tags/Badges (e.g., NO `variant="destructive"`). Even for destructive actions or important statuses, use only neutral variants (`outline`, `ghost`, `secondary`, or standard `default` if it maps to black/white). Do not try to make Buttons or Tags colored. No red, green, or blue colors should appear anywhere in the UI.
